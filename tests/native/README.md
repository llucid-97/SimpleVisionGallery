# Generated native regression suite

Run `tests/run_native_transitions.py` through agent_queue_mcp on an exclusive host. Set `GALLERY_SIMULATOR_UDID` to a task-owned, shut-down visionOS 26.1 Simulator; `GALLERY_GENERATED_TEST_BUNDLE` to a dedicated generated-data-only app bundle that has full Photos access on that simulator; and `GALLERY_SIMULATOR_TEST_TEAM` to the local signing team identifier. The runner refuses an already-running simulator, builds a fresh production-source copy, and shuts down only the simulator it booted. Do not point it at real user photos or Pali. The fixture substitutes a unique generated PhotoKit bin title while retaining the production comparison/mutation code. A synthetic vault key and optional deterministic delay do not test user authentication. Generated test PhotoKit assets remain on the test simulator.

The default suite runs native navigation/frame timing and generated PhotoKit mixed-bin/two-window/lock/failure checks. It does not test the Photos-to-vault system confirmation. Pass `--photos-system-prompt` only when able to approve the generated one-photo prompt; the run otherwise times out. Approve only for this generated fixture. A timeout/failure is not a pass. Timing uses programmatic actions and CADisplayLink, not headset photons or real hand taps. Actual spatial scene appearance and user comfort need a headset check.

The runner requires retained warm navigation model readiness under 50 ms and immediate Move enqueue under 50 ms. It reports frame callback gaps over 50 ms as warnings, not a full performance pass; cold or in-flight successors are identified by their load mode. The suite does not measure restore frame responsiveness, physical slider drags, or headset appearance and comfort.
